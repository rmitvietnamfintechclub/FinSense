# API endpoints

Quick reference for the frontend sprint. Base path is `/api`; the server runs on localhost during
this sprint and the address belongs in exactly one place in each app.

`docs/openapi.yaml` is the contract source of truth — this file is a readable summary of it, not a
second contract. If the two disagree, the spec wins and this file is wrong. Response types are
generated from the spec into `frontend/types/generated/api.types.ts` by `frontend/types/generate.sh`;
never hand-write them.

Every endpoint is public except the four under `/audit`, which require `Authorization: Bearer <jwt>`
and answer `401` without one. There is no refresh endpoint: a `401` from anywhere means the
eight-hour session is over.

`window` is always one of `24h`, `48h`, `72h` (the interface labels these 1d / 2d / 3d) and defaults
to `24h`. A `window` outside those three is a `422`, not a silent fallback.

| Endpoint | What it is for | What it returns |
|---|---|---|
| `GET /health` | Liveness probe. Touches nothing, so it stays green even when Mongo is down. | `{ status: "ok" }` |
| `GET /dashboard/summary` | The four metric cards at the top of the dashboard. Deliberately has **no** `window` param — these totals must not move when the user changes the window. | `total_articles` and `total_events` (all-time counts of the whole database), `total_tickers` (the VN30 basket size — always 30, never a growing count), and `last_updated` (newest `updated_at` across all events, `null` on an empty database). |
| `GET /dashboard/gauge?window=` | The Fear & Greed radar. Recency-weighted blend of every scored event in the window, so it describes the whole market, not a selected ticker. | `market_score` in `[-1, 1]`, `is_empty` (true = nothing to score; render "No data for this window", never a needle at zero), the three-way `positive_count` / `neutral_count` / `negative_count`, plus `scored_events` and `total_events_in_window` — the second is larger when some events carry no score yet. |
| `GET /dashboard/events?window=&page=&limit=` | The dashboard's Events view: events ranked by how many articles cover them inside the window. Default `limit` is 5, matching Load more. | `events[]` of `rank` (global, already offset by page), `cluster_id`, `event_title`, `total_articles`, `sources` (a `{source: count}` map — render whatever keys arrive, never a hardcoded source list) and `tickers_mentioned[]`. Plus `window`, `page`, `limit`, `has_more`. |
| `GET /dashboard/events/{cluster_id}/articles` | The articles behind one event row, for expand-in-place. There is no event detail page; this replaces it. Not window-scoped — the row was already chosen by a windowed query. | `articles[]` of `source`, `article_title` (falls back to the event title), `article_url`, `published_at`, `score` (`null` when the extraction produced nothing — show "no data", not `0.00`) and `ai_confidence`. Plus `total_articles` (all articles in the event) and `articles_shown` (rows returned). **The two differ by design**: only one representative article per source carries an extraction, and low-confidence sources are excluded. `404` on an unknown `cluster_id`. |
| `GET /dashboard/tickers?window=&page=&limit=` | The dashboard's Tickers view: tickers ranked by how many events mention them inside the window. Ranked by coverage, never by sentiment. Default `limit` is 5. | `tickers[]` of `rank`, `ticker`, `company_name`, `event_count`, `sentiment_score` and `is_empty`. Plus `window`, `page`, `limit`, `has_more`. Capped at 30 rows in total, because that is the whole basket. |
| `GET /tickers` | The VN30 directory that backs the search box. Static vocabulary read from `core/data/ticker_metadata.json`, never the database, unaffected by any window. Fetch once and hold it. | `tickers[]` of `ticker`, `company_name` and `aliases[]` — 30 rows, sorted by symbol, unpaginated. The aliases carry the Vietnamese names, which is what lets "Hoa Phat" match HPG. |
| `GET /ticker/{symbol}?window=` | The ticker detail header: the live score plus the identity-card counts. Computed at request time from `event_clusters`, not read from history. The detail page passes `window=72h`. | `ticker`, `company_name`, `sentiment_score` (`null`, never `0.0`, when there is no data), a `gauge` breakdown with the same score and the three bucket counts, `article_count`, `event_count`, `last_updated`, and `is_empty_state`. `404` on a symbol outside VN30. |
| `GET /ticker/{symbol}/history?days=` | The chart series. `days` is `7`, `30` or `90` (default `30`) and is a **calendar** window, not a row count. Reads the pre-computed daily rollup only — no live scoring, no gap filling. | `data[]` of `date` (`YYYY-MM-DD`), `daily_sentiment_score` (`null` = no news that day → draw no bar) and `closing_price` (`null` = market closed or the fetch failed). Oldest first. Shorter than `days` when the end-of-day batch has not run that far back — normal, not an error. |
| `GET /ticker/{symbol}/events?window=&page=` | Events mentioning this ticker, newest first, 5 per page. Window-scoped on the same vocabulary as everything else; the detail page passes `window=72h` so the whole page covers one span of time. | `items[]` of `cluster_id`, `event_title`, `created_at`, `article_count`, `sentiment_score` (this ticker's entry, `null` if no source cleared the confidence threshold) and `source_breakdown[]` — one row per source with its `source`, `score` for this ticker, `article_title` and `article_url`. Plus `ticker`, `window`, `page`, `has_more`. |
| `GET /ticker/{ticker}/sentiment?window=` | The single live score for one ticker, with no counts or events attached. Predates the detail endpoint above; use `/ticker/{symbol}` for the detail page. | `ticker`, `window`, `score` (`null` on the empty state) and `is_empty`. `404` on a symbol outside VN30. |
| `POST /auth/login` | Admin sign-in. JSON body `{ username, password }` — not form-encoded. The only unauthenticated write in the API, and there is no self-registration endpoint. | `access_token` (JWT, valid eight hours, carries the admin's id and display name) and `token_type: "bearer"`. `401` on bad credentials. |
| `GET /audit/summary` | The three metric cards on the audit panel. Re-fetch after every approve or correction. | `total_articles`, `audited_articles`, and `pending_review` (the difference — it counts articles that were never selected for extraction and so can never be audited, which is why it does not reach zero). |
| `GET /audit/articles?status=&sort=&search=&page=` | The audit queue. One row per **(cluster, source)** pair, because a source entry is what an admin approves. `status` is `pending` (default), `audited` or `all`; `sort` is `newest`, `oldest`, `confidence_asc` or `confidence_desc`; `search` matches a ticker symbol or a title. 10 rows per page. | `items[]` carrying the row (`cluster_id`, `source`, `article_title`, `event_title`, `article_url`, `published_at`, `ticker_count`, `ai_confidence`, `is_audited`), the read-only left panel (`content_fed_to_ai`, `model_version`, `prompt_version`), the editable scores (`ticker_sentiments`, `concept_sentiments` — current values, an admin's where corrected), the unchangeable reference (`original_ticker_sentiments`, `original_concept_sentiments` — always the AI's own output, correct even on a third open), and `last_audit`. Plus `page`, `has_more`, `total`. |
| `PATCH /audit/events/{cluster_id}/{source}` | Approve or correct one source entry. Body is `{ action_type: "approve" \| "correct", error_type?, corrected_ticker_sentiments?, corrected_concept_sentiments? }`. Corrections are **partial** — send only what changed. The admin identity comes from the token, never the body. | `success`, `cluster_id`, `source`, `action_type`, and `aggregated_analysis_recomputed` (true when scores actually changed and the cluster blend was rebuilt). `400` when an approve carries correction fields, when a correct has no `error_type`, or when a corrected score is `null`; `404` when the cluster or source does not exist. |
| `GET /audit/log?page=` | The append-only correction history — every approve and every correction, newest first, 10 per page. A re-audit adds a row and never rewrites one. | `items[]` of `cluster_id`, `source`, `admin_id`, `admin_name`, `action_type`, `error_type`, `old_ticker_sentiments` / `new_ticker_sentiments`, `old_concept_sentiments` / `new_concept_sentiments`, and `performed_at`. Plus `page`, `has_more`. |
